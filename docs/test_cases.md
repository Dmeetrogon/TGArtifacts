# Приложение Д. Тест-кейсы функционального тестирования TGArtifacts

## Методология

Тестирование построено на параметрической матрице из пяти осей:

| Ось | Значения |
|-----|----------|
| **Версия Telegram Desktop** | 4.x (legacy, `version < 2001014`) / 6.x (modern, `version >= 2001014`) |
| **Passcode** | Не установлен / Установлен / Неверный |
| **Тестируемая функция** | `info`, `export-session`, `extract-cache`, `bruteforce`, `audit`, `scan` |
| **Граничные условия** | Одиночный аккаунт / Мультиаккаунт / Пустая tdata / Повреждённый файл |
| **Объём кэша** | Малый (< 50 файлов) / Большой (> 200 файлов) / Стриминговые фрагменты |

Для каждого тест-кейса фиксируется: описание действия, ожидаемый результат, фактический результат, статус, комментарий.

---

## Тестовые условия

### Условие №1 — Linux
- Ubuntu 24.04, Python 3.12
- Telegram Desktop 4.x и 6.x
- tdata — криминалистические копии директорий

### Условие №2 — Windows
- Windows 11, Python 3.12
- Telegram Desktop 4.x и 6.x
- tdata — криминалистические копии директорий

## Раздел 2. Unit-тесты

Unit-тесты покрывают отдельные компоненты вне зависимости от полного tdata: TDF-парсер, Qt Data Stream, модуль расшифровки, детектор типов файлов, деривацию ключей. Общее количество: **400+**

### 2.1 TDF-парсер (`parsers/tdata_parser.py`)

| ID | Описание | Ожидаемый результат |

| UT-001 | Валидный TDF-файл: magic `TDF$`, версия >= 1000000 | Успешный парсинг, возврат данных |
| UT-002 | Неверный magic (не `TDF$`) | `ValueError: Invalid TDF magic` |
